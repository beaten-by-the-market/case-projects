# 04 배당기준일 태깅 — 정관의 결산배당 기준일 조항

코스피 825사·코스닥 1,784사 정관(사업보고서 첨부본)에서 **결산배당을 받을 주주를 정하는 기준일** 조항을 찾아 회사마다 태그 하나를 달았다.
코스닥은 아래 [코스닥](#코스닥-2026-11-16-추가-사용자-지시) 절 — 같은 지침·발췌로, Claude API 대신 Claude Code 서브에이전트가 판별했다.
사용자 지시(2026-11-16): 정관에서 '배당을 받을 주주를 확정하기 위한 기준일'·'주주명부에 기재된 주주' 같은 내용을 찾아
아래 셋 중 하나를 단다. 정관 전체를 LLM 에 넣지 말고, 관대한 키워드로 해당 조항 앞뒤를 추린 뒤 LLM 으로 판별한다.

| 태그 | 뜻 | 대표 문구 |
|---|---|---|
| `정관no` | 이사회로 정하는 때 — 정관이 날짜를 고정하지 않는다 | "이사회결의로 제1항의 배당을 받을 주주를 확정하기 위한 기준일을 정할 수 있으며, … 2주 전에 이를 공고" |
| `정관yes` | 정관상 결산일 — 결산기말(또는 정관이 박은 날) 현재 주주 | "제1항의 배당은 매 결산기말 현재의 주주명부에 기재된 주주 또는 등록된 질권자에게 지급한다" |
| `정관yesorno` | 정관상 결산일, 단 이사회로 정하는 때에도 할 수 있다 | "매 사업연도 종료일 현재 … 지급하되 … 단, 회사는 이사회결의로 배당을 받을 주주를 확정하기 위한 기준일을 정할 수 있으며" (한화리츠) |
| `확인필요` | 원문이 없거나 결손이라 판단할 수 없다 | — |

`tag_current` 의 근거 종류(`basis_kind`): 사업보고서 751 · 주총소집공고 72(정기주총 62 · 제출 뒤 9 · 확인필요 대체 1) · 주총소집공고+사업보고서 본문 1(OCI) · 전년도 사업보고서 1(SK이터닉스).
웹페이지 '배당기준일' 탭은 `tag_current` 를 보인다.

* 첨부 정관 기준 `정관no` 437사(53.0%), 개선 방향 문구가 있는 회사(`정관no`+`정관yesorno`) 444사(53.8%).
* **상장협 집계와 대조** — 상장협·코스닥협 2026.4.14 집계('25.12.31 기준 12월 결산 상장사, 리츠·스팩·외국사 등 제외)는 유가증권시장 501/795사가 정비했다고 했다.
  이 표의 12월 결산 주권 790사에서 `정관no`+`정관yesorno` 는 첨부 정관 기준 430사로 71사 모자랐는데, 2026.3 정기주총 안건(사업보고서보다 먼저 접수된 소집공고)을
  반영한 지금은 **503사**(`정관no` 497 · `정관yesorno` 6)로 2사 차이다. 첨부 정관이 대부분 그 주총 **전** 판이었던 것이 차이의 거의 전부였다.
  상장협은 '기존 정관으로 가능한 회사'도 포함하는 등 기준이 조금 달라 남은 차이까지 맞추지는 않았다.
* 제출 뒤 안건으로 `정관yes → 정관no` 가 되는 회사 9사: 케이아이이, SK아이이테크놀로지, 삼양사, 신풍, 스틱인베스트먼트, 세방전지, 유나이티드, 프리티, 한국화장품제조.
  (보해양조는 첨부 정관이 이미 안건 반영본이라 태그가 같다.) 가결 여부는 주총 결과 공시로 확인하지 않았다.

**근거가 온 자리 (`route`)** — 배당 조 직접 708 · 배당 조가 기준일 조를 참조 113 · 기준일 조가 배당을 명시 1(한국전력공사) · 없음 3.
참조형 113사 중 `정관yes` 91사는 2021~2023 표준정관 문구("제13조 제1항에서 정한 날 현재")이고, `정관no` 19사는 참조된 조 자체가
"주주총회의 소집 기타 필요한 경우 이사회의 결의로 정한 날"이라 정관 어디에도 고정일이 없는 경우다(HD현대 계열 등).

**중간·분기배당** (결산배당 태그와 따로)

|---|---|---|---|---|---|
| 중간배당 (`interim`) | 97 | 233 | — | 481 | 14 |
| 분기배당 (`quarterly`) | 125 | 77 | 4 | 606 | 13 |

결산배당은 `정관no` 인데 분기배당은 3·6·9월 말 고정인 회사가 68사다(첨부 정관·제출 뒤 안건 기준 — 2026.3 정기주총 반영 뒤 지금은 85사) — 분기배당은 법(자본시장법 제165조의12)이 2025.1.21 에야 풀렸고
표준정관 분기배당 조도 2025.1.24 에 바뀌었다(regulation-history).

**증권 구분** — 리츠 23사: `정관no` 7 · `정관yes` 14 · `정관yesorno` 2. 외국주권 1(`정관no`), 주식예탁증권 1(싱가포르 법인, `정관yes`).

## 한계

* **`tag` 는 사업보고서 첨부 정관 시점이다.** 12월 결산 회사의 첨부 정관은 대개 그해 3월 정기주총 **전** 판이다.
  `tag_current` 는 소집공고 안건 중 결산배당 기준일을 바꾸는 것을 KIND 가결로 확인해 반영했다 — 제출 뒤 공고(s09d)와, 2026-11-17 부터는 원본 제출
  **전** 90일 안에 접수된 공고(그해 정기주총, s09i)까지. 90일보다 앞선 임시주총 안건, KIND 결과공시 안건 표를 읽지 못한 공고(코스닥 2), 결과공시가
  없거나 정관 안건이 없던 공고(코스피 2 · 코스닥 2)는 반영하지 않았다(특이사항 '주총 안건 가결 확인 못 함'). 보해양조처럼 안건 반영본을 미리 첨부한 회사도 있다.
* 정관이 '정할 수 있다'고 해도 실제로 배당액을 먼저 정하고 기준일을 뒤로 잡았는지는 별개다 — 공시(「현금ㆍ현물배당을 위한 주주명부폐쇄(기준일) 결정」,
  「현금ㆍ현물배당 결정」의 배당기준일)나 사업보고서의 '배당관련 예측가능성' 기재로 따로 확인해야 한다.
* 스캔 정관(이미지 164·PDF 일부)은 Opus 전사문으로 판별했다. 인용할 때는 `charter_url` 원본과 대조한다.
* `interim`·`quarterly` 의 `없음` 은 "발췌에 그 조가 보이지 않음"이다. 발췌 앵커에 중간·분기배당이 있어 실제 없음과 거의 같지만 전문으로 확인하지는 않았다.
* LLM 판별은 같은 입력이라도 다시 돌리면 드물게 달라질 수 있다 — 결과(`s09b_results.jsonl`)를 저장해 두고 다시 보내지 않는다.

## 다시 돌리기 · 다른 표에 쓰기

```bash
python -X utf8 scripts/s09a_dividend_excerpt.py                 # 발췌 (s09_targets.json 이 있으면 그것을 쓴다)
python -X utf8 scripts/s09b_dividend_tag_llm.py submit          # 결과 없는 회사만 배치로 (비용 발생)
python -X utf8 scripts/s09b_dividend_tag_llm.py status | collect
python -X utf8 scripts/s09d_dividend_after_agm.py               # 제출 뒤 안건 (동기, 비용 발생)
python -X utf8 scripts/s09e_agm_result_kind.py                  # 그 안건의 가결 여부 (KIND)
python -X utf8 scripts/s09f_prev_charter.py fetch               # 확인필요 회사 전년도 정관 (DART 웹 — 다른 수집과 겹치지 않게)
python -X utf8 scripts/s09f_prev_charter.py transcribe          #   스캔이면 Opus 전사 (비용)
python -X utf8 scripts/s09f_prev_charter.py tag                 #   판별 (비용)
python -X utf8 scripts/s09c_dividend_build.py --queue           # 결과표(tag_current 포함) + 사람 검토 목록
python -X utf8 scripts/s09g_dividend_evidence.py                # 근거 조항 · 스캔 쪽 잘라 내기 (Windows OCR)
python -X utf8 scripts/s10_dividend_site.py                     # site/dividend.js
# 코스닥 (API 없이 서브에이전트 — 실제로 돌린 순서)
python -X utf8 scripts/s09a_dividend_excerpt.py --sfx kosdaq --src data/final/kosdaq_charter.json
python -X utf8 scripts/s09b_dividend_tag_llm.py pack --sfx kosdaq --chars 100000   # in/{code}.txt · packets.json
#   서브에이전트: data/interim/s09b_agent_kosdaq/지시.md + 묶음의 종목코드 → out/{code}.json (전문 재판별은 {code}.full.json)
python -X utf8 scripts/s09b_dividend_tag_llm.py ingest --sfx kosdaq             # 스키마 검사 → s09b_results_kosdaq.jsonl
python -X utf8 scripts/s09c_dividend_build.py --sfx kosdaq && python -X utf8 scripts/s09h_kosdaq_review.py
python -X utf8 scripts/s09d_dividend_after_agm.py --sfx kosdaq --pack            # 제출 뒤 안건 → 서브에이전트(s09d_agent_kosdaq/지시.md)
python -X utf8 scripts/s09d_dividend_after_agm.py --sfx kosdaq --ingest
python -X utf8 scripts/s09e_agm_result_kind.py --sfx kosdaq
python -X utf8 scripts/s09f_prev_charter.py fetch --sfx kosdaq --codes 452200,228670,362320,067010
#   서브에이전트: data/interim/s09f_agent_kosdaq/지시.md → out/{code}.json ({output, notices})
python -X utf8 scripts/s09f_prev_charter.py ingest --sfx kosdaq
python -X utf8 scripts/s09c_dividend_build.py --sfx kosdaq
python -X utf8 scripts/s09g_dividend_evidence.py --sfx kosdaq
# 사업보고서보다 먼저 접수된 그해 정기주총 안건 (s09i — 2026-11-17, 두 시장 같은 순서)
python -X utf8 scripts/s09i_pre_agm.py targets [--sfx kosdaq]   # E006 목록 캐시에서 원본 접수일 전 90일 공고 (호출 없음)
python -X utf8 scripts/s09i_pre_agm.py fetch   [--sfx kosdaq]   # OpenDART document.xml → data/agm_pre{,_kosdaq}/…/정관의변경.txt
python -X utf8 scripts/s09i_pre_agm.py pack    [--sfx kosdaq]   # DIVAMEND 걸린 회사 → 서브에이전트(s09i_agent{,_kosdaq}/지시.md)
python -X utf8 scripts/s09i_pre_agm.py ingest  [--sfx kosdaq]
python -X utf8 scripts/s09e_agm_result_kind.py [--sfx kosdaq]   # DIVAMEND 공고 전부의 KIND 결과(판별 전에도 받음) · 저장된 안건 표로 다시 판정
python -X utf8 scripts/s09c_dividend_build.py  [--sfx kosdaq]   # tag_current = 첨부 정관 → s09i 안건 → s09d 안건
# 사업보고서 없는 상장회사(absent_charter, e6) — 텍스트·PDF 먼저, 스캔은 전사본이 나온 뒤
python -X utf8 scripts/s09a_dividend_excerpt.py --sfx absent --src data/final/absent_charter.json
python -X utf8 scripts/s09b_dividend_tag_llm.py pack --sfx absent --exclude-ocr  # → 서브에이전트 → ingest --sfx absent
python -X utf8 scripts/s09c_dividend_build.py --sfx absent                      # basis_kind = charter_source_doc
python -X utf8 scripts/s10_dividend_site.py                                      # 코스피·코스닥(+absent) 함께
```

지침(`tagging-guide.md`)을 고치면 프롬프트 해시가 바뀐다. 결과 파일을 치우거나 새 `--sfx` 로 다시 보내고, `s09c_summary.json` 의 `prompt_sha256` 이
하나인지 확인한다.
