# 01 수집 사양

이 문서는 **규칙**을 적는다. 무엇을, 어디서, 어떤 기준으로 골라 담았는지가 여기 있다.
열 이름·형식·파일 위치와 용어 풀이는 [02-데이터사전](02-데이터사전.md)에, 날짜별로 확인한 사실과 건수는 [03-검증기록](03-검증기록.md)에 있다.
다른 문서는 규칙을 "01-수집사양 R3" 처럼 **R1~R8** 로 가리킨다. 세부 항목은 `R3-2` 처럼 붙인다.

## R1 목록 — 최종보고서만, 회사마다 1건

**한 줄로.** 조회기간에 접수된 사업보고서 **최종본**을 모두 받는다. 한 회사가 여러 건이면 **결산기가 가장 늦은 1건**만 남긴다.

| 번호 | 항목 | 규칙 | 근거 |
|---|---|---|---|
| R1-1 | API | OpenDART `list.json` | OpenDartReader `dart.list()` 가 부르는 것과 같다 |
| R1-2 | 공시유형 | `pblntf_detail_ty=A001` (사업보고서) | |
| R1-3 | 최종보고서 | `last_reprt_at=Y` | `dart.list(..., final=True)` 와 같다 (사용자 지시 2026-11-16) |
| R1-4 | 구간 | 조회기간을 3개월 이하 구간으로 나눠 부른다(`11-16~02-15`, `02-16~05-15` …). 구간 사이에 겹친 접수번호는 한 번만 둔다 | 회사를 지정하지 않으면 검색기간이 3개월로 제한된다 |
| R1-5 | 제외 | `사업보고서제출기한연장신고서`. 보고서명에서 접두어와 `(YYYY.MM)` 를 뺀 본문이 `사업보고서` 가 아닌 행은 뺀다 | A001 에 같이 나온다 |
| R1-6 | 회사별 1건 | 같은 `corp_code` 안에서 결산기(`report_period`)가 가장 늦은 것 → 같으면 접수번호가 늦은 것. 뺀 행은 `logs/s01_dropped_older.csv` | 사용자 지시(2026-11-16): 한 해에 여러 번 냈으면 가장 최근 것만 |

**왜 결산기를 먼저 보나.** `last_reprt_at=Y` 는 **기간 안에 접수된 최종본**을 준다. 그래서 2024 사업연도 보고서라도 최종 정정본이 이 기간에 접수됐으면 목록에 들어온다(`fiscal_year` 로 구분된다).
접수일로 고르면 옛 사업연도 보고서의 늦은 정정본이 이길 수 있다.

**예.**

| 회사 | 기간 안의 사업보고서 | 남은 행 |
|---|---|---|
| 한창 (005110) | `[첨부추가]사업보고서 (2025.12)` 20260326001334 · `[기재정정]사업보고서 (2022.12)` 20260625000263 | 2025.12. 접수일로 골랐다면 2022 사업연도가 남았다 (`s01_reports_all.json`) |
| 마스턴프리미어리츠 (6개월 결산) | `사업보고서 (2025.09)` 20251218000386 · `사업보고서 (2026.03)` 20260618000369 | 2026.03. 앞 기수가 빠진다 |

## R2 사업연도·결산월

**한 줄로.** 보고서명 끝 `(YYYY.MM)` 은 결산기 말 연월이다. 연도를 사업연도로, 달을 결산월로 쓴다.

| 번호 | 열 | 규칙 |
|---|---|---|
| R2-1 | `fiscal_year` | `YYYY` (정수). OpenDART 정기보고서 API 의 `bsns_year` 와 같은 규칙이다 |
| R2-2 | `settle_month` | `MM` 을 정수로 (`09` → `9`) |
| R2-3 | `report_period` | `YYYY.MM` 원문 그대로 (문자열) |
| R2-4 | 읽지 못할 때 | 보고서명 끝에 `(YYYY.MM)` 이 없으면 세 열 모두 빈 값 |

**왜.** 규칙이 `bsns_year` 와 같아야 이 목록의 행을 OpenDART 정기보고서 API 결과와 그대로 맞출 수 있다.

**예.** 03-검증기록에서 `alotMatter.json`(배당, 사업보고서 `11011`)을 연도별로 불러 확인했다.

| 회사 | 보고서 | `fiscal_year` | `settle_month` | 그 보고서가 조회된 `bsns_year` |
|---|---|---|---|---|
| 방림 (9월 결산) | `사업보고서 (2025.09)` 20251222000124 | 2025 | 9 | 2025 |
| 마스턴프리미어리츠 (6개월 결산) | `(2025.03)` 20250610000442 · `(2025.09)` 20251218000386 | 2025 | 3 · 9 | 둘 다 2025 |
| 마스턴프리미어리츠 | `(2026.03)` 20260618000369 | 2026 | 3 | 2026 |

6개월 결산 리츠는 한 해에 사업보고서가 두 번(예: 03·09) 나오고 둘 다 같은 `fiscal_year` 다. 목록에는 R1-6 에 따라 결산기가 늦은 1건만 남는다.

## R3 `rcept_no_new` — 최종본이 `[첨부정정]` 인 행만

**한 줄로.** 최종본이 `[첨부정정]` 이면 그 화면에는 사업보고서 본문이 없다. DART 화면의 본문 목록(`family`)에서 가장 최근 본문의 접수번호를 찾아 `rcept_no_new` 에 넣는다. 다른 행은 `rcept_no` 를 그대로 쓴다.

사용자 기존 프로젝트 규칙(`dart_disclosure/snowflake_dart_annualrep.ipynb` 의 `get_recent`,
`seibro-api/seibro_api/dart_report.py` 의 `_get_rcept_no_new`)을 그대로 따른다.

| 번호 | 규칙 | `rcept_no_new_status` |
|---|---|---|
| R3-1 | `https://dart.fss.or.kr/dsaf001/main.do?rcpNo={rcept_no}` 를 연다 | |
| R3-2 | `<select id="family">`(+본문선택+) 에서 `null` 이 아닌 **첫 옵션**의 `rcpNo` 를 `rcept_no_new` 로 넣는다 | `family_first` |
| R3-3 | R3-2 의 접수번호가 `rcept_no` 보다 늦으면(첨부정정 **뒤** 본문) 상태 끝에 `_after_amend` 를 붙인다 | `family_first_after_amend` |
| R3-4 | `family` 가 비어 있으면 `rcept_no` 로 둔다 | `fallback_no_family` |
| R3-5 | 화면을 받지 못했으면 `rcept_no` 로 둔다 | `fallback_not_fetched` |
| R3-6 | 다른 행(접두어 없음·`[기재정정]`·`[첨부추가]`)은 `rcept_no_new = rcept_no` | 빈 값 |

**왜.** `[첨부정정]` 화면의 본문은 정정신고서와 바뀐 첨부뿐이다. 원래 본문은 `family` 에 있다.

**알아 둘 화면 동작** (03-검증기록에서 확인):

* `family`·`att` 는 **보고서 가족 전체**의 목록이다. 원본·첨부정정·기재정정 어느 접수번호로 열어도 같은 목록이 나오고, 최신 본문이 맨 위다.
  그래서 첨부정정 **뒤에** 기재정정이 또 나온 보고서는 첫 옵션이 그 뒤 본문이다(R3-3).
  단 이 목록은 `last_reprt_at=Y` 라 최종본이 `[첨부정정]` 인 행만 대상이므로, 그 뒤 기재정정이 있으면 그 기재정정이 최종본이 된다 — 실제로는 생기지 않아야 한다.
* 이 목록은 수집시점(2026-11-16 11:51 ~ 12:10) 기준이다. 행마다의 시각은 `s03_main.json` 의 `fetched_at`(= 캐시 파일 저장 시각), 범위는 `manifest.json` 의 `fetched.dart_main` 에 있다. 그 뒤 정정공시가 나오면 목록이 바뀐다.
* `[첨부추가]` 는 새 접수번호를 받지 않는다. 원 공시 행의 보고서명 앞에 `[첨부추가]` 만 붙는다(첨부 목록에 `[추가]` 문서가 원 접수번호로 들어간다). 그래서 R3 대상이 아니다.

**예.**

| 회사 | 목록 행 | 화면에서 본 것 | 결과 |
|---|---|---|---|
| 제주항공 | `[첨부정정]` 20260515002339 | 본문 목차는 정정신고 + `내부회계관리제도운영보고서` 뿐. `family` = `20260318001439 사업보고서` | `rcept_no_new` = 20260318001439 (`family_first`) |
| HL홀딩스 | `[기재정정]` 20260813001221 | 원본 20260318001627 · 첨부정정 20260318001665 · 기재정정 20260813001221 세 번호 모두 같은 `family`(20260813001221 → 20260318001627, 최신이 위) | 첨부정정 뒤 기재정정이 나와 기재정정이 최종본이 됐다 → R3 대상 아님 |
| 엔케이 | `[첨부추가]` 20260323001528 | `att` 에 `2026.08.14 [추가] 자기주식보고서` 가 같은 접수번호로 붙는다 | 대상 아님 |

## R4 소속시장 — KIND 기준일 현재 목록 한 번

**한 줄로.** 사용자 결정(2026-11-16): **기준일 현재 상장사 목록을 KIND 에서 한 번만 받아 그 시장을 쓴다.** 접수일별 스냅샷은 쓰지 않는다.

| 번호 | 항목 | 규칙 |
|---|---|---|
| R4-1 | 목록 | KIND 상장종목현황 상세 `listed_issue_status(selDate=기준일, mktId, secugrpId)` — `krx-kind-data-api` 패키지 |
| R4-2 | 받는 범위 | 유가(`STK`): 주권 `ST`·외국주권 `FS`·투자회사 `MF`·부동산투자회사 `RT`·`DR` / 코스닥(`KSQ`): `ST`·`FS`·스팩 `SP`·`DR` / 코넥스(`KNX`): `ST`. `secugrpId` 를 비우면 결과가 없어서 증권구분별로 받는다 |
| R4-3 | 휴장일 | 기준일의 유가 주권 목록이 비어 있으면 하루씩 앞당겨(최대 9일 전까지) 목록이 나오는 첫 날을 쓴다. 쓴 날짜는 `market_basis_date` |
| R4-4 | 맞추기 | 종목코드로 맞추고, 없으면 회사명(공백·`(주)`·`㈜`·`주식회사` 를 지우고 영문은 대문자로)으로 맞춘다. 목록에 없으면 `기타` |
| R4-5 | 값 | `코스피` · `코스닥` · `코넥스` · `기타` |
| R4-6 | 대조 | KIND 시장과 OpenDART `corp_cls` 가 다른 행은 `logs/s02_market_vs_corp_cls.csv` 에 남긴다 |
| R4-7 | 목록에 없는 코스피 회사 | KIND 코스피 회사(종목코드 기준, 중복 제거) 중 코스피로 맞춘 행이 없는 회사마다 근거를 남긴다(s02b). 고유번호(`corpCode.xml`)는 종목코드 → 상장 회사명 → 종목코드가 빈 항목 중 이름이 하나뿐인 것 순으로 찾는다(기준일 당일 상장사는 종목코드가 아직 비어 있을 수 있다, `corp_code_match_by`). OpenDART 는 그 고유번호로 ① `A001` 전체 이력(`last_reprt_at=N`, 1999-01-01 ~ 기준일, 연장신고서 제외) ② 조회기간의 모든 공시(최종본) ③ `company.json` 의 결산월. KIND 는 ④ 공시 상세검색(`repIsuSrtCd=A+종목코드`, 조회기간, 최종본) ⑤ 제목이 `기타신고사항` 인 공시는 본문의 '제목' 칸을 읽어 영업보고서·자산운용보고서·결산·감사·정관 변경·투자설명서 갱신·그 밖으로 묶는다. 사유 `reason_code` 는 앞에서부터: `report_in_window`(조회기간 안 사업보고서가 있는데 목록에 없음 — 수집 누락 의심, 0건이어야 함) → `new_listing`(상장일이 조회기간 안이고 상장 뒤 사업보고서 없음. 첫 결산기 말 + 90일을 기한으로 적는다, 자본시장법 제159조) → `no_annual_report`(이력 0건) → `no_report_in_window`. KIND 상장현황 요약(`listed_issue_summary`)도 받아 회사 수·종목 수를 함께 남긴다(기준일부터 거꾸로 평일만, 주말 날짜는 직전 영업일 값이 나와 날짜 표기가 어긋난다) |

**왜.** 사용자 결정이다. 처음에는 접수일마다 KIND 스냅샷을 받으려 했으나(하루 3~10회 호출), 기준일 현재 목록 한 번으로 바꿨다(03-검증기록).

**한계.** 제출 당시가 아니라 **기준일 현재** 시장이다. 제출 뒤 상장폐지된 회사는 `기타`, 이전상장한 회사는 옮겨 간 시장,
제출 뒤 신규상장한 회사는 그 시장으로 나온다. OpenDART `corp_cls` 도 현재 기준이다.

**R4-7 왜.** 코스피 정관 표는 사업보고서에서 출발하므로, 조회기간에 사업보고서를 내지 않은 상장사는 들어올 수 없다. 사용자가 KIND 코스피 회사 수(829)와 표의 행 수(825)가 다른 이유를 물어(2026-11-16) 화면에 근거를 남기기로 했다. 투자회사가 KIND '기타신고사항'으로 보고한다는 점은 사용자가 알려 주었고 본문 제목으로 확인했다(03-검증기록).

**예.** 한창(005110)은 2026-03-26 제출 때 유가증권시장 상장사였지만(KIND 그날 목록) `corp_cls='E'` 로 나온다. 기준일 현재 목록에도 없어서 `market` 은 `기타` 다.

## R5 정관 — 코스피 행

**한 줄로.** 코스피 행(R4 의 `market=코스피`)마다 공시 화면의 첨부서류 목록에서 `정관` 을 고른다. 그 원문 HTML·텍스트·스캔 이미지를 내려받는다.

| 번호 | 단계 | 규칙 |
|---|---|---|
| R5-1 | 첨부문서 목록 | s03 에서 받은 `main.do` 의 `<select id="att">`. OpenDartReader `attach_docs(rcp_no)` 와 같은 규칙으로 읽는다(`title`, `url = https://dart.fss.or.kr/dsaf001/main.do?{value}`). `attach_docs` 는 `http://` 로 만드는데 여기서는 `https://` 만 다르다. 마스터 노트북 `8. 검증` 의 (7) 셀이 라이브러리 결과와 대조한다 |
| R5-2 | 정관 고르기 | 제목 `YYYY.MM.DD [태그] 이름` 에서 이름이 `정관` 인 것. 띄어쓰기(`정 관`)와 뒤에 붙은 괄호 설명(`정관(전문)`)은 허용한다. 여럿이면 날짜가 가장 늦은 것 → 같은 날이면 `[정정]` → 목록 앞쪽. 후보 수는 `n_charter_att` |
| R5-3 | 원문 | 첨부 `main.do`(= `attach_docs` 의 `url`)의 목차 노드(OpenDartReader `sub_docs()` 와 같은 정규식)로 `viewer.do` 주소를 만든다. 노드가 없으면 화면의 첫 `viewDoc(…)` 호출을 쓴다. 노드가 겹치면(상위 절이 하위 절을 포함) 바깥 노드만 받는다. 노드마다 `viewer_NN.html` 로 저장하고, 텍스트로 바꿔 차례로 `charter.txt` 에 잇는다(파일 형식은 02) |
| R5-4 | 이미지 | 원문 HTML 의 `<img src="/report/download.do?dcmNo=…&flNm=…">` 를 순서대로 받는다(Referer = viewer 주소). DART 화면 공용 그림(`/images/common/`)은 빼고, 같은 `src` 는 한 번만 받는다. 파일 이름은 순번 3자리 + `flNm` 의 확장자(없으면 `.jpg`). 받지 못한 이미지는 `images[].error` 와 `n_image_errors` 에 남긴다 |
| R5-5 | 종류 | 공백 제외 본문 글자 수 `text_chars`(이미지 캡션·이미지 자리표시·표 칸 구분 `\|` 는 세지 않는다)와 이미지 수 `n_images` 로 나눈다. `text`(이미지 0·글자 ≥200) · `image`(이미지 ≥1·글자 <200) · `mixed`(이미지 ≥1·글자 ≥200) · `pdf`(이미지 0·글자 <200 이고 원문에 PDF 링크가 있음 → R5-8) · `empty`(그 밖, 이미지 0·글자 <200) |
| R5-7 | 글자 인식(OCR) | `content_type` 이 `image`·`mixed` 인 문서만. Windows 내장 OCR(Windows.Media.Ocr, 언어 `ko`, `winocr` 패키지). 회색조 → 긴 변 3,000px 로 맞춤 → 대비 조금 늘림. 같은 높이의 조각 줄은 왼쪽부터 다시 잇는다. 동그라미 숫자(①②, 엔진이 못 읽음)는 이미지에서 찾아 넣는다. 날짜 점 빠짐(`2012.0323`→`2012.03.23`)·`재N조`→`제N조`·자주 틀리는 핵심 낱말 12개(`사재`→`사채`, `종회`→`총회` 등, `TERM_FIXES`)만 고친다. `charter.txt` 를 그대로 두고 이미지 자리 줄 바로 아래에 그 장의 글자를 넣어 `charter_ocr.txt` 로 쓴다. 이미지 sha256 이 같고 오류가 없으면 다시 하지 않는다 |
| R5-8 | PDF 정관 | 원문 화면이 `<A href='/report/download.do?dcmNo=…&flNm=….pdf'>` 링크뿐인 정관(처음 실행에서 '빈 문서' 31개 — 예 CJ대한통운 `씨제이대한통운_정관.pdf`). PDF 를 `pdf/001.pdf …` 로 받고('%PDF' 로 시작하는지 확인), PyMuPDF 로 쪽마다 글자층을 읽는다. 공백 뺀 글자가 30자 미만인 쪽은 스캔으로 보고 긴 변 3,000px 로 그려 R5-7 과 같은 글자 인식을 한다. `charter_pdf.txt` 는 `[PDF 001: 파일명] → pdf/001.pdf` 아래 쪽마다 `[쪽 N]`(글자 인식한 쪽은 `[쪽 N · OCR]`). PDF sha256 이 같으면 다시 하지 않는다 |
| R5-9 | Opus 전사 | 사용자 지시(2026-11-16): 스캔 쪽 전부를 Claude Opus 5.5 로 다시 읽는다. 쪽 하나 = 요청 하나, Message Batches API(값 50%), `effort: low`, `max_tokens` 8000. 이미지는 회색조로 바꿔 긴 변 2,576px·3.6MP 이하(Opus 가 줄이지 않고 읽는 최대 크기)로 맞춘 JPEG(품질 85). 프롬프트: 보이는 글자만 그대로, 고치지·요약하지 않음, 원문자·기호 그대로, 표는 ` \| `, 못 읽으면 `[?]`. `charter_llm.txt` 는 이미지 정관이면 `charter.txt` 틀에 쪽마다 전사를, PDF 정관이면 `charter_pdf.txt` 의 `[쪽 N · OCR]` 쪽만 전사로 바꿔 `[쪽 N · Opus]` 로 표시. Windows OCR 결과(`charter_ocr.txt`)는 그대로 둔다 |
| R5-6 | 한 번만 | 정관 문서(`rcpNo`·`dcmNo`)마다 **한 번만** 받는다. `att` 가 가족 전체 목록이라 같은 보고서 가족은 어느 접수번호로 열어도 같은 정관을 가리킨다. 그 문서를 쓰는 행은 `used_by_rcept_no` 에 남는다. 폴더에 `meta.json` 이 있으면 다시 받지 않는다 |

**글자 인식 품질 (2026-11-16, 121개 문서 2,370장 시험).** 1,300px 이상인 장(전체의 77%)은 글자 약 99% 가 맞는다. 800~1,300px 은 97~98%,
900px 아래 작은 스캔은 80~93% 로 나쁘다. 흔한 오류는 ㅊ→ㅈ(`저리`←처리, `설지`←설치), ㅐ·ㅖ 세로획→`0H`·`1`(`판0H`←판매), 한 글자 줄 빠짐,
로고·QR 쓰레기 줄, 머리말·쪽번호가 본문에 섞임. 기계가 읽은 글자이므로 인용할 때는 이미지와 대조한다.

**Opus 전사 시험 (2026-11-16, 3장).** Windows OCR 이 틀린 곳을 모두 맞게 읽었다 — 하이트진로 2쪽 `판0H업`·`저리`·`생물`·`등 중개` → **판매업·처리·샘물·동 중개**,
한온시스템 6쪽(486×701 작은 스캔) `받행`·`1.㈌ 역` → **발행·1,000 억 원**, 비비안 PDF 18쪽 원문자 ①②③ 정확. 장당 입력 약 3,700·출력 약 900 토큰.

**왜.** 사업보고서 첨부서류에 정관이 들어간다(OpenDartReader 사용 안내의 삼성전자 20220308000798 예시, 03-검증기록).
정정본은 원본의 첨부를 물려받으므로, 정관은 원본 접수번호로 붙어 있는 경우가 많다.

**예.**

## R6 주주총회 — 코스피 행

**한 줄로.** 코스피 행마다 사업보고서 **원본 최초 접수일**부터 기준일까지 **접수된** 주주총회소집공고(최종본)를 센다. 공고마다 원문 XML 을 받아 '정관의 변경' 절이 있는지 본다. 있으면 그 절을 텍스트로 따로 저장한다.

사용자 지시·결정(2026-11-16).

| 번호 | 항목 | 규칙 |
|---|---|---|
| R6-1 | 기간 시작 | 사업보고서 **원본 최초 접수일** `orig_rcept_dt`. s03 `family` 의 본문 접수번호와 행 자신의 접수번호 중 가장 이른 것이 `orig_rcept_no` 이고, 그 앞 8자리가 `orig_rcept_dt` 다. 정정이 없으면 행 자신 |
| R6-2 | 기간 끝 | 기준일(2026-11-16). 양끝 포함 |
| R6-3 | 목록 | OpenDART `list.json` `pblntf_detail_ty=E006`(주주총회소집공고) `last_reprt_at=Y`. 회사별로 부르지 않고 시장 전체를 3개월 구간으로 받는다(가장 이른 `orig_rcept_dt` ~ 기준일). 그다음 코스피 회사(`corp_code`)만 거른다 |
| R6-4 | 셈 | **소집공고 접수일**이 기간 안인 최종본 수 = `agm_count` (사용자 결정: 주총 개최일 기준이 아님). 원문을 받지 못한 공고도 센다(`agm_errors`) |
| R6-5 | 원문 | 공고마다 OpenDART `document.xml` ZIP → `data/agm/{종목코드}_{회사명}/{접수일}_{rcept_no}/` 에 ZIP 안 파일을 그대로 둔다. 본문 파일은 `{rcept_no}.xml`, 그런 이름이 없으면 가장 큰 파일 |
| R6-6 | 정관의 변경 찾기 | ① **코드**: `TITLE@AASSOCNOTE="L0-0-2-2-0"`. `III. 경영참고사항 › 2. 주주총회 목적사항별 기재사항` 아래 안건유형 절 제목에 붙는 코드다(증권발행공시규정 제3-15조③ 2호, `agm-comparison/docs/01-DART코드정리.md`). 문서의 모든 TITLE 에서 찾는다. ② **제목**: 코드가 하나도 없는 공고는 '목적사항별'·'기재사항' 이 든 제목 뒤에 나오는 TITLE 중 글자가 `정관`+(`의`)+(`일부`)+`변경`/`개정` 으로 **시작하는** 것(띄어쓰기 무관. 예: `정관의 변경`·`정관 일부 변경`·`정관 개정`). 앞에 `□■○●◎※-` · `1.` `1)` · `가.` `가)` · `(1)` 이 붙어도 된다. ③ 본문 파일에서 못 찾고 ZIP 에 파일이 더 있으면 나머지 파일에서 ①②를 다시 해 본다. 찾은 방법은 `detect` |
| R6-7 | 절 | 찾은 TITLE 의 부모 SECTION 전체. 절이 여럿이면 빈 줄을 두고 이어 `정관의변경.txt` 로 저장한다(파일 형식은 02) |
| R6-8 | 주총 구분 | 원문에서 **처음 나오는** 구분 하나만 → `agm_kind` (`정기`·`임시`·`종류`). 찾는 순서: ① 제목 `주주총회 소집공고 (제10기 임시주주총회)`·`(임시)` ② 소집 문장 `…임시주주총회를 아래와 같이 개최` ③ `제N기 정기`. 원문 뒤쪽의 이사회 활동표('임시주주총회 소집의 건')·정관 조문에도 같은 낱말이 나와서, 여러 개를 모으면 틀린다(처음 규칙은 247건 중 157건을 '정기·임시'로 잘못 냈다 — 03) |
| R6-9 | 결과 열 | `agm_charter_amend_count` = 위 절이 있는 공고 수. `agm_charter_amend_txt` = 그 공고들의 `정관의변경.txt` 경로 목록 (= 정관개정안건 본문 URL) |

**해석 주의.** 소집공고는 주총 2주 전, 사업보고서는 주총 1주 전까지 낸다. 그래서 12월 결산 회사의 3월 정기주총 소집공고는
대개 사업보고서보다 **먼저** 접수되어 이 셈에 들어가지 않는다. 사업보고서에 붙은 정관이 그 정기주총에서 바뀌었는지는 이 열로 알 수 없다.

**예.**

* 기간 시작 — HL홀딩스 목록 행은 `[기재정정]` 20260813001221 이지만 `family` 의 가장 오래된 본문은 20260318001627 이다.
  그래서 `orig_rcept_dt` = `20260318`, 셈 기간은 2026-03-18 ~ 2026-11-16 이다 (`s03_main.json`).
* 해석 주의 (형식 예시, 실제 회사 아님) — 12월 결산 회사가 소집공고를 `2026-03-0X` 에, 사업보고서를 `2026-03-1X` 에 냈다면
  기간은 `2026-03-1X` 부터라 그 소집공고는 세지 않는다. 그 뒤 기준일까지 접수된 임시주총 소집공고는 센다.

## R7 코스닥 — 같은 규칙을 코스닥 행에

**한 줄로.** 사용자 지시(2026-11-16): 코스피에 한 정관 수집(R5)·소집공고 수집(R6)·목록에 없는 회사 점검(R4-7)을 코스닥에도 **똑같이** 한다.
규칙은 바꾸지 않는다. 코스피에는 없던 데이터가 나와 R7-4·R7-5 만 정했다.

| 번호 | 항목 | 규칙 |
|---|---|---|
| R7-1 | 대상 | R4 의 `market=코스닥` 행 전부(1,784). DART 화면(R3·R5-1)도 코스닥 행 전부를 연다 — 코스피 s03 은 `[첨부정정]` 행만 시장 무관으로 열었으므로, 그 41행은 코스피 때 받은 화면 저장본을 쓴다(`fetched_at` 이 다르다) |
| R7-2 | 같은 코드 | 코스닥 단계(`sNNk_kosdaq_*.py`)는 코스피 스크립트를 import 해 **함수를 그대로** 쓰고, 모듈 전역 경로(`CHARTER` · `INTERIM` · `AGM` · `LLM` · `PAGES_F` …)만 `scripts/_kosdaq.py` 의 `patch()` 로 코스닥 위치로 바꾼다. 시장이 코드에 들어 있는 대상 고르기(`main()`)만 코스닥용으로 다시 둔다. 그래서 R3·R5·R6 을 고치면 코스닥에도 그대로 적용된다. `s02c` 만 `s02b` 의 복사본이라 따로 맞춘다 |
| R7-3 | 저장 위치 | `data/charter_kosdaq/` · `data/agm_kosdaq/`(폴더 구조는 코스피와 같다) · 중간 파일 `data/interim/kosdaq/`(파일 이름은 코스피와 같다) · Opus 결과 `data/raw/llm_ocr_kosdaq/`(요청 ID `p00001…` 가 시장마다 따로 매겨지므로 분리) · OpenDART 근거 `data/raw/opendart_absent_kosdaq/` · KIND 근거 `data/raw/kind/absent_kosdaq/`. DART 화면 캐시(`dart_main` · `dart_att`)와 PDF 렌더(`pdf_pages`)는 접수번호·문서번호로 이름이 붙어 같이 쓴다 |
| R7-4 | 본문 + PDF | 원문 화면에 본문 텍스트(글자 ≥200)가 있으면서 같은 정관의 PDF 링크도 붙은 정관은 R5-5 대로 `text` 다. `s04c` 는 PDF 링크만 보고 `meta.json` 을 `pdf` 로 바꾸므로 `text` 로 되돌리고 `content_type_note` 에 이유를 남긴다. PDF 는 받아 `charter_pdf_txt` 로 둔다 |
| R7-5 | 받을 수 없는 PDF | DART 가 PDF 대신 599B HTML '안내'(미서비스)를 주거나, `application/pdf` 로 와도 내용이 DRM 암호화 파일(`<## NASCA DRM FILE …##>`)이면 받지 못한 것으로 둔다(`pdf.json` 의 `error`). 그 정관은 `charter_status=ok` 이지만 정관 전문이 없다(R7-7) |
| R7-6 | 목록에 없는 코스닥 회사 | R4-7 과 같은 절차를 KIND 코스닥 회사에(s02c). 결과표 열은 코스피 `kospi_absent` 열 + `corp_code_match_by` · `kind_titles_window`(KIND 공시 제목별 건수 — 피씨엘처럼 근거가 KIND 공시 제목에만 있는 회사가 있다) |
| R7-8 | PDF 글의 제어문자 | PDF 글자층에서 나온 제어문자(`\x00-\x08` · `\x0b` · `\x0c` · `\x0e-\x1f` · `\x7f`)는 `charter_pdf.txt` 에서 지우고 글자 수를 다시 센다(`s04ck` 끝 단계, `--clean-only` 로 그것만). 지운 수는 `pdf.json` 의 `control_chars_removed`. 셀레스트라 352770 PDF 는 띄어쓰기마다 `\x01` 이 붙어(4,689자) 문구 검색이 안 됐다. 코스피 PDF 31개에는 없다 |
| R7-7 | 정관 전문 | `charter_fulltext_txt` 는 코스피와 같은 순서(Opus 전사 → Windows OCR → PDF 글 → `charter.txt`). 다만 `text` 는 PDF 가 함께 붙어도 `charter.txt`(R7-4), PDF 를 하나도 읽지 못한 `pdf` 는 빈 값(R7-5) — 실패 안내 줄뿐인 파일을 정관 전문으로 가리키지 않는다 |

**왜 함수를 import 하나.** 코스피와 코스닥이 같은 규칙이어야 두 시장을 한 표로 비교할 수 있다. 코드를 복사하면 한쪽만 고쳐질 수 있다.
코스닥 작업 때 다른 세션이 코스피 스크립트를 고치고 있어 공용 파일을 건드리지 않는 방법을 골랐다(03-검증기록).

**예.** MDS테크(086960)·LB인베스트먼트(309960) — 본문 1만 4천여 자 + `정관(… 개정).pdf` 링크, 본문과 PDF 글의 유사도 0.998·0.976 → `text`(R7-4).
이씨에스·청담글로벌·민테크는 DART '안내' 화면, 레이는 DRM 파일 → 정관 전문 없음(R7-5).

## R8 사업보고서가 없는 회사의 정관 — 다른 근거문서에서

**한 줄로.** 사용자 지시(2026-11-17): R4-7·R7-6 에서 '목록에 없는 회사'로 남은 회사 중 **신규상장·투자회사**는 증권신고서(또는 증권신고서 + 주총 소집공고)·홈페이지 등에서
정관을 찾아 지금 화면(근거문서 탭) 안에 넣는다. 정관을 다루는 규칙(R5)·소집공고 규칙(R6)은 그대로이고, **어느 문서에서 정관을 가져오는지**만 다르다.

| 번호 | 항목 | 규칙 |
|---|---|---|
| R8-1 | 대상 | `kospi_absent` ∪ `kosdaq_absent` 중 `reason_code` 가 `new_listing`·`no_annual_report` 인 회사. 예전엔 사업보고서를 냈던 `no_report_in_window`(피씨엘)는 대상이 아니다 |
| R8-2 | 근거문서 (`charter_source_doc`) | 값은 네 가지로 고정. ① **증권신고서** — 조회기간 OpenDART 공시(최종본) 중 보고서명에 '증권신고서'가 든 것의 가장 늦은 접수번호(지분증권 · 증권예탁증권 · 합병). ② **분할계획서** — 인적분할 재상장은 자기 증권신고서가 없다. 모회사의 회사분할결정 주요사항보고서 첨부 `계약서(계획서)`(분할계획서)의 '분할신설회사 정관(안)' 쪽만 뽑는다. 처음 값 이름 '분할공시(모회사)'는 모회사 정관으로 읽혀 바꿨다(사용자 지적 2026-11-17). 웹페이지 정관 링크는 '분할신설회사 정관(안) (계획서 24~38쪽)', 근거 그림 쪽 번호는 계획서 원문 쪽. 모회사의 분할 증권신고서에 붙은 `정관`은 **모회사 자신의 정관**이라 쓰지 않는다. ③ **기타신고사항** — 투자회사가 KIND '기타신고사항'으로 낸 정관 개정 공지의 첨부(문서 후보 '기타공시첨부서류'). ④ **홈페이지** — KIND 공지 없이 홈페이지에만 게시된 정관(지금은 없음). KIND 기타신고사항이 홈페이지 게시를 가리키면 근거문서는 ③ **기타신고사항**이고 정관 파일만 그 게시본을 쓴다(맥쿼리인프라, 사용자 지적 2026-11-17). ②~④ 는 `s04e` 의 `MANUAL` 에 근거와 함께 손으로 적는다 |
| R8-3 | 받기 | DART 문서는 R5-1~R5-6 그대로(정관 고르기는 R5-2, 분할계획서는 이름에 `계약서(계획서)` 가 든 첨부 중 R5-2 의 날짜·정정 순). 분할계획서 원문 전체는 `data/charter_absent_src/` 에 두고, 정관 쪽 이미지만 `data/charter_absent/…/{첨부일자}_{dcmNo}_p{시작}-{끝}/` 로 복사해 스캔 정관 문서로 만든다(`meta.json` 의 `subset_of`·`subset_pages`). KIND·홈페이지 PDF 는 s04c 의 글 뽑기(R5-8) 그대로, Word(.docx)는 문단·표를 `charter.txt` 로 옮겨 `text` 로 둔다 |
| R8-4 | 스캔 쪽 전사 | 사용자 지시(2026-11-17): Claude API 를 쓰지 않는다. `llm pages` 가 R5-9 와 같은 이미지(회색조, 긴 변 2,576px)와 쪽 목록을 만들고, 다른 세션의 에이전트가 같은 지시문으로 읽어 `results.jsonl` 에 넣는다. 요청 ID 는 폴더·파일·쪽에서 만든 고정 값(`a` + 12자리) — 문서가 더해져도 넘긴 쪽의 ID 가 밀리지 않는다 |

**왜.** 정관 표는 사업보고서 첨부에서 출발해, 조회기간에 사업보고서가 없는 상장회사는 정관을 볼 수 없었다. 증권신고서(상장 때)·분할계획서(재상장 때)·투자회사의 KIND 공시에는 그 회사의 정관이 붙어 있다.

**해석 주의.** 증권신고서·분할계획서의 정관은 **상장 전(또는 분할 전) 시점**이다. 상장 뒤 주총에서 바뀌었을 수 있으므로 R8-5 의 '정관의 변경' 절을 함께 본다(배당특이사항에 '증권신고서 + 주총 소집공고'로 적는 경우).

**예.** 한화머시너리앤서비스홀딩스(0220W0): ㈜한화 회사분할결정 20260514000430 → 분할계획서 `[첨부3] 분할신설회사의 정관(안)` 24~38쪽(제1조 "한화머시너리앤서비스홀딩스 주식회사"). ㈜한화 분할 증권신고서 20260604000183 의 `정관`은 ㈜한화의 것.

## 요청 예절

**DART 웹은 IP 당 1분에 100건이 한도다** (사용자 확인 2026-11-16). 넘으면 연결이 끊기며 막힌다. 한 프로세스에서 순차로 부르고,
같은 PC 의 다른 DART/OpenDART 수집과 동시에 돌리지 않는다.

| 대상 | 최소 간격 | 분당 상한 |
|---|---|---|
| DART 화면 (`main.do` · 첨부 `main.do` · `viewer.do`) | 1초 | **80건** — 화면·이미지·재시도를 합쳐 호스트 단위로 센다 |
| DART 이미지 (`download.do`) | 0.5초 | (위와 같이 묶임) |
| OpenDART `list.json` | 0.35초 | 80건 |
| OpenDART `document.xml` | 0.5초 (응답 대기 120초) | (위와 같이 묶임) |
| KIND | 받을 때마다 0.5초 쉼 | — |

* 분당 상한은 `_common.Http.PER_MIN` 이 **호스트 단위로** 한 프로세스 안 모든 연결을 합쳐 센다. 처음에는 화면용(1초)·이미지용(0.5초) 연결이 간격을 따로 세어 분당 ~180건이 됐고 막혔다 (03).
* **IPv4 로만 접속한다.** 이 PC 망은 IPv6 를 NAT64 로 내보내는데, 차단이 그 출구 주소에만 걸린 적이 있다(`curl -6` 끊김, `curl -4` 200). 막혔는지 볼 때는 둘을 따로 시험한다.

* 실패하면(HTTP 429·5xx 포함) 3·6·12·24초씩 기다리며 4번까지 시도한다. 연속 5건 실패면 차단으로 보고 600초 쉰다 (`_common.Http`).
* **다른 세션이 DART 웹을 잠깐 써야 하면** 수집을 멈추고 넘겨준다: 프로세스를 멈춘 뒤 `meta.json` 이 없는(받던) 문서 폴더만 지운다 → 상대가 60초 뒤 시작 →
  상대가 끝났다고 알리면 그 마지막 요청 60초 뒤 다시 켠다(분당 창을 비우려고). 단계마다 `meta.json` 으로 이어받는다(2026-11-16 코스닥 s04k, 03).
* OpenDART 키가 일일 한도(`status=020`)에 걸리면 `.env` 의 다음 키(`DART_API_KEY*`)로 바꾼다.
* 모든 원본 응답은 저장하고, 다시 실행하면 저장본을 읽는다 (02 "캐시").
