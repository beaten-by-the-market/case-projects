## 용어 풀이

| 용어 | 뜻 | 이 데이터에서 |
|---|---|---|
| 접수번호 (`rcept_no`) | DART 가 공시 한 건을 접수할 때 주는 14자리 번호. 앞 8자리가 접수일(`YYYYMMDD`)이다. DART 화면 주소에서는 `rcpNo` 라고 쓴다 | 행의 키. `https://dart.fss.or.kr/dsaf001/main.do?rcpNo={rcept_no}` 로 열린다 |
| 최종본 · 최종보고서 | 한 보고서를 정정해 여러 번 냈을 때 가장 마지막에 낸 것. OpenDART `last_reprt_at=Y`(= OpenDartReader `final=True`)가 최종본만 준다 | 사업보고서·소집공고 행은 모두 최종본이다 (01 R1, R6) |
| 기재정정 | 본문 내용을 고쳐 다시 낸 정정공시. 보고서명 앞에 `[기재정정]` 이 붙는다. 새 접수번호와 새 본문이 생기고 `family` 맨 위에 오른다 | `amend_tag` = `[기재정정]` |
| 첨부정정 | 첨부서류만 바꿔 낸 정정공시. 보고서명 앞에 `[첨부정정]` 이 붙는다. 새 접수번호를 받지만 그 화면 본문은 정정신고서와 바뀐 첨부뿐이다 | 원래 본문의 접수번호를 `rcept_no_new` 에 따로 둔다 (01 R3) |
| 첨부추가 | 이미 낸 공시에 첨부서류를 더 붙인 것. 새 접수번호를 받지 않는다. 원 공시 행의 보고서명 앞에 `[첨부추가]` 만 붙고, 첨부 목록에 `[추가]` 문서가 원 접수번호로 들어간다 | `rcept_no_new` 대상이 아니다 |
| `rcept_no_new` | 사업보고서 **본문**을 볼 접수번호 | `[첨부정정]` 행만 `rcept_no` 와 다르다 |
| `family` 선택상자 | DART 공시 화면(`main.do`)의 `<select id="family">`(+본문선택+). 같은 보고서 가족(원본·정정본)의 본문 목록이다. 최신이 맨 위이고, 어느 접수번호로 열어도 같다 | `rcept_no_new`(01 R3)와 원본 최초 접수일(01 R6-1)을 여기서 읽는다 |
| `att` 선택상자 | 같은 화면의 `<select id="att">`. 보고서 가족 전체의 첨부서류(감사보고서·정관 등) 목록이다. OpenDartReader `attach_docs()` 가 읽는 목록이고, 항목 제목은 `YYYY.MM.DD [태그] 이름` 꼴이다 | 정관을 여기서 고른다 (01 R5) |
| `dcmNo` | DART 문서번호. 한 접수번호 안의 본문·첨부 문서 하나하나에 붙는다 | 정관 문서 하나 = `rcpNo` + `dcmNo`. 정관 폴더 이름 `{첨부일자}_{dcmNo}` |
| 원본 최초 접수 | 정정하기 전에 처음 낸 사업보고서. `family` 에서 가장 오래된 본문이다 | `orig_rcept_no` · `orig_rcept_dt`. 주총 셈 기간의 시작 (01 R6-1) |
| 소집공고 (주주총회소집공고) | 주주총회 일시·안건을 미리 알리는 공시. OpenDART 공시유형 `E006`. 주총 2주 전까지 낸다(사업보고서는 주총 1주 전까지) | `agm_*` 열, `agm_notices`, `data/agm/` (01 R6) |
| 결산기 · 사업연도 · 결산월 | 결산기는 회계기간이 끝나는 연월이고, 사업보고서 이름 끝 `(YYYY.MM)` 이 그것이다. 사업연도는 그 연도, 결산월은 그 달 | `report_period` · `fiscal_year` · `settle_month`. 9월 결산 `(2025.09)` 는 사업연도 2025 (01 R2) |
| 기준일 | 이 데이터를 고정한 날, 2026-11-16 | 조회기간의 끝이자 소속시장을 판정한 날, 주총 셈 기간의 끝. 단 DART 화면과 원문은 수집시점 기준이다 |
| 수집시점 | DART 화면·원문을 실제로 받은 때. 그 뒤 정정공시가 나오면 DART 의 내용이 바뀐다 | 수집시점 기준이다. 범위는 `manifest.json` 의 `fetched`(`dart_main`·`charter_docs`·`agm_xml`), 건마다는 `fetched_at` |
| 코스피 | 유가증권시장. KIND `STK` | `market` = `코스피` (기준일 현재, 01 R4) |

> **`charter` 라는 이름.** 정관의 영문 정식 명칭은 **Articles of Incorporation (AOI)** 이다 — DART 소집공고 XML 의 '정관의 변경' 절 영문 제목이
> `□ Changes to articles of incorporation`(`TITLE@ENG`, 코드 `L0-0-2-2-0`). 폴더·열·스크립트 이름의 `charter` 는 짧게 쓰려고 붙인
> 식별자일 뿐이다(미국식 charter 는 설립증서만 뜻하고 bylaws 와 따로지만, 한국 정관은 둘을 한 문서로 겸한다). 영문 표기가 필요하면
> "정관 (Articles of Incorporation)" 으로 쓴다.

## 읽는 법

* **JSON** — 레코드 배열(`manifest.json` 만 객체), UTF-8. `pd.read_json(path, dtype=False)` 로 읽어야 접수번호·종목코드의 앞자리 0 이 살아 있다. 목록 열은 파이썬 list 로 들어온다.
* **CSV** — `utf-8-sig`(엑셀에서 바로 열린다). 판다스로는 `dtype=str` 로 읽는다. 목록 열은 `;` 로 이은 문자열이다.
* **XLSX** — `kospi_charter.xlsx` 하나뿐이다. 아래 "엑셀" 표를 본다.
* **경로 열** — 모두 케이스 폴더(`kospi-charter/`) 기준 상대경로이고 구분자는 `/` 다. 파일을 열 때는 케이스 폴더 경로를 앞에 붙인다.
* **빈 값** — JSON 에서 해당 없는 열은 `null`, 접두어·증권구분처럼 비어 있을 수 있는 문자열은 `""` 다. CSV 에서는 둘 다 빈 칸이다.

**목록 열**

| 파일 | 목록 열 | JSON | CSV | XLSX |
|---|---|---|---|---|
| `kospi_charter` | `agm_rcept_nos` · `agm_kinds` · `agm_charter_amend_rcept_nos` · `agm_charter_amend_txt` · `agm_charter_amend_dart_url` | 배열 | `;` 로 이은 문자열 | 줄바꿈으로 이은 문자열. 링크 열은 첫 항목에 링크 |
| `agm_notices` | `used_by_rcept_no` | 배열 | `;` 로 이은 문자열 | — |
| `charter_docs` | `used_by_rcept_no` | 배열 | `;` 로 이은 문자열 | — |

빈 목록은 JSON 에서 `[]`, CSV 에서 빈 칸이다.

```python
import pandas as pd
from pathlib import Path

CASE = Path("kospi-charter")          # 케이스 폴더. 경로 열은 모두 여기 기준
kc = pd.read_json(CASE / "data/final/kospi_charter.json", dtype=False)   # 앞자리 0 유지

# 정관 원문 한 건 읽기
row = kc[kc["charter_status"] == "ok"].iloc[0]
text = (CASE / row["charter_txt"]).read_text(encoding="utf-8")

# 정관을 바꾼 소집공고: 목록 열을 한 줄에 하나로 펼친다 (pandas 1.3+)
amend = (kc[kc["agm_charter_amend_count"] > 0]
         [["corp_name", "agm_charter_amend_rcept_nos", "agm_charter_amend_txt"]]
         .explode(["agm_charter_amend_rcept_nos", "agm_charter_amend_txt"]))
amend["body"] = [(CASE / p).read_text(encoding="utf-8") for p in amend["agm_charter_amend_txt"]]

# CSV 로 읽을 때: 문자열로 받고 목록 열은 직접 나눈다
csv = pd.read_csv(CASE / "data/final/kospi_charter.csv", dtype=str, keep_default_na=False)
csv["agm_rcept_nos"] = csv["agm_rcept_nos"].map(lambda s: s.split(";") if s else [])
```

## 자주 묻는 것

### `market` 은 공시를 낼 때의 시장인가?

아니다. 기준일 현재 KIND 목록의 시장이다(01 R4). 제출 뒤 상장폐지된 회사는 `기타`, 이전상장한 회사는 옮겨 간 시장, 신규상장한 회사는 그 시장으로 나온다.
`corp_cls` 도 현재 기준이다. 예: 한창(005110)은 2026-03-26 제출 때 유가증권시장 상장사였지만 `corp_cls` = `E`, `market` = `기타` 다.

### 3월 정기주총이 `agm_count` 에 없다.

주총은 **소집공고 접수일**이 [`orig_rcept_dt`, 기준일] 안에 들 때만 센다(01 R6). 소집공고(주총 2주 전)가 사업보고서(주총 1주 전)보다 먼저 접수되므로,
12월 결산 회사의 3월 정기주총은 대개 빠진다. 사업보고서에 붙은 정관이 그 정기주총에서 바뀌었는지는 이 열로 알 수 없다.

### 정관에서 글자 검색이 안 된다.

**정관 전문을 한 파일로 읽으려면 `charter_fulltext_txt` 를 쓴다** — 종류에 따라 `charter.txt`(텍스트)·`charter_llm.txt`(스캔·PDF 스캔 쪽을 Opus 가 옮긴 글, 실패 쪽이 없을 때)·`charter_ocr.txt`(Windows OCR)·`charter_pdf.txt`(PDF) 가운데 가장 읽을 만한 것을 가리킨다.

`charter_content_type` = `image` 면 스캔 이미지다. `charter.txt` 에는 `[이미지 001: 캡션] → img/001.jpg` 같은 자리표시만 있다. 글자는 **`charter_ocr_txt`**(글자 인식 결과 `charter_ocr.txt`)에서 찾는다.
기계가 읽은 글자라 틀린 곳이 있다(선명한 장 약 99%, 작은 스캔 80~93%, 01 R5-7). `mixed` 는 글자와 이미지가 섞였다 — `charter_ocr.txt` 에 둘 다 들어 있다.
`pdf` 는 정관이 PDF 파일로 첨부된 경우다 — 글은 `charter_pdf_txt`(PDF 글자층, 글자층 없는 쪽만 글자 인식)에 있다.

### `charter_rcpNo` 가 `rcept_no` 와 다르다.

정상이다. 정정본은 원본의 첨부를 물려받아서, 정관이 원본 접수번호로 붙어 있는 경우가 많다(01 R5). 예: HL홀딩스 행 `rcept_no` 20260813001221, 정관 `rcpNo` 20260318001627.

### `[첨부정정]` 행의 DART 화면에 사업보고서 본문이 없다.

그 화면에는 정정신고서와 바뀐 첨부뿐이다. 본문은 `rcept_no_new` 로 연다(01 R3).

### 지금 DART 에서 열어 보면 본문·첨부 목록이 다르다.

`family`·`att` 는 수집시점(2026-11-16 11:51 ~ 12:10, `s03_main.json` 의 `fetched_at`) 기준이다. 그 뒤 정정공시가 나오면 바뀐다.
정관 원문과 소집공고 XML 도 각자의 수집시점 기준이고, 그 범위는 `manifest.json` 의 `fetched` 에 있다. 캐시를 지우고 다시 받으면 반영된다(아래 "캐시").

### 원문을 받지 못한 소집공고도 `agm_count` 에 드나?

든다. 그런 공고 수는 `kospi_charter.json` 의 `agm_errors` 에 있다. `agm_notices` 에서는 받지 못한 공고의 `error` 에 이유가 있고,
아직 처리하지 않은 공고는 `has_charter_amend` 가 빈 값이다.

### 한 회사가 사업보고서를 여러 번 냈는데 1건만 있다.

회사마다 결산기가 가장 늦은 1건만 남긴다(01 R1-6). 뺀 보고서는 `logs/s01_dropped_older.csv` 에 있다.

## 열 정의

## 텍스트 파일 형식

### `charter.txt`

* UTF-8. 문단마다 한 줄. 표는 행마다 칸을 ` | ` 로 잇는다.
* 스캔 이미지 자리에는 `[이미지 001: 캡션] → img/001.jpg` 줄이 들어간다. 표 칸 안의 이미지는 `[이미지 001] → img/001.jpg` 로 칸에 붙는다.
* 원문 노드가 여럿이면 `viewer_01` 부터 차례로 잇는다.

실제 예 (앞 몇 줄):

```
# data/charter/000080_하이트진로/20260318_11137773/charter.txt   (image)
정 관
[이미지 001: 표지] → img/001.jpg
[이미지 002: 16-1] → img/002.jpg

# data/charter/000020_동화약품/20260318_11139570/charter.txt   (text)
정 관
동화약품주식회사 정관
제1조(상호)
이 회사는 동화약품주식회사(영문:DONG WHA PHARM.CO.,LTD.)라 한다.
```

### `charter_ocr.txt`

* `charter.txt` 의 줄을 모두 그대로 두고, 이미지 자리 줄(`[이미지 NNN: …] → img/NNN.jpg`) **바로 아래**에 그 장의 글자 인식 결과를 줄마다 넣는다.
* 같은 이미지가 다시 나오면 글자는 처음 자리에만 넣는다. 인식에 실패한 장은 `[OCR 실패: …]` 한 줄.
* 자리 줄이 없는 이미지는 끝에 `[이미지 NNN: charter.txt 에 표시 줄 없음] → img/NNN.jpg` 아래로 붙는다.
* 동그라미 숫자(①②)는 이미지에서 찾아 넣었고, 날짜 점 빠짐·`재N조`·핵심 낱말 12개 오인식만 고쳤다(01 R5-7). 그 밖의 오인식은 그대로다.

실제 예 (앞 몇 줄, 오인식 포함):

```
# data/charter/000080_하이트진로/20260318_11137773/charter_ocr.txt
[이미지 002: 16-1] → img/002.jpg
개정 (2011년 7월 28일)
제 1 조 (상호)
이 회사는 하이트진로 주식회사라 한다. 영문으로는 HITEJINRO CO., LTD.라 표기한다.
(9) 유리제품의 제조·가공·판0H업            ← '판매업' 의 오인식
```

### `charter_llm.txt`

* 이미지 정관: `charter.txt` 줄을 그대로 두고 이미지 자리 줄 바로 아래에 그 쪽의 Opus 전사. 자리 줄이 없는 이미지는 끝에 붙인다.
* PDF 정관: `charter_pdf.txt` 를 그대로 두고, 글자층이 없어 글자 인식했던 쪽만 `[쪽 N · Opus]` 와 Opus 전사로 바꾼다.
* 실패한 쪽은 `[Opus 실패: …]` 한 줄. 표는 행마다 ` | `, 읽지 못한 글자는 `[?]`, 글자 없는 쪽은 `[빈 쪽]`.

### `charter_pdf.txt`

* `[PDF 001: 원래 파일 이름] → pdf/001.pdf` 아래 쪽마다 `[쪽 N]` 줄과 그 쪽의 글. 글자층이 없어 글자 인식한 쪽은 `[쪽 N · OCR]`.
* 받기·뽑기에 실패하면 `[받기 실패: …]`·`[글자 뽑기 실패: …]` 한 줄.

### `정관의변경.txt`

* UTF-8. 문단 한 줄. 표는 행마다 칸을 ` | ` 로 잇고, 칸 안 줄바꿈은 ` / ` 로 바꾼다. DART 줄바꿈 엔티티 `&cr;` 는 줄바꿈이 된다.
* 표 뒤에는 빈 줄을 하나 둔다. 빈 줄이 겹치면 하나로 줄인다.
* 이미지(`IMAGE`·`IMG`)와 `COLGROUP`·`COL`·`FILENAME` 요소는 뺀다.
* 절이 여럿이면 빈 줄을 두고 잇는다 (01 R6-7).

형식 예시 (실제 공고 아님):

```
□ 정관의 변경
(문단 한 줄)
(칸) | (칸) | (칸)
(칸) | (칸 첫 줄 / 칸 둘째 줄) | (칸)
```

## 캐시 (`data/raw/`, git 제외)

| 폴더 | 내용 |
|---|---|
| `opendart_list/` | `list.json` 응답 페이지 (`A001_Y_{시작}_{끝}_p{쪽}.json` · `E006_Y_{시작}_{끝}_p{쪽}.json`, 날짜 `YYYYMMDD`, 쪽 3자리) |
| `kind/` | KIND 상장 목록 (`listed_{날짜}_{시장}_{증권구분}.csv`) |
| `dart_main/` | 보고서 `main.do` HTML (`{rcept_no}.html`) — `family`·`att` 의 원본. 파일 저장 시각이 `s03_main.json` 의 `fetched_at` |
| `dart_att/` | 정관 첨부 `main.do` HTML (`{rcpNo}_{dcmNo}.html`) — viewer 주소의 원본 |

정관 `viewer.do` HTML 은 캐시가 아니라 `data/charter/…/viewer_NN.html` 에, 소집공고 XML 은 `data/agm/` 에 있다.

캐시를 지우면 다음 실행에서 다시 받는다. DART 화면의 `family`·`att` 는 수집시점 기준이라, 지우고 다시 받으면 그사이 정정공시가 반영된다.
단 정관·소집공고 폴더에 `meta.json` 이 있으면 그 문서는 다시 받지 않는다.
