# 정관 결산배당 기준일 태깅

정관마다 **결산배당을 받을 주주를 누가·언제 정하는지**를 세 태그 중 하나로 단다. 판단 기준의 원본은
[references/tagging-guide.md](references/tagging-guide.md)이고(LLM 시스템 프롬프트가 그 파일에서 그대로 나온다),
왜 이런 문구들이 생겼는지는 [references/regulation-history.md](references/regulation-history.md)에 있다.

| 태그 | 뜻 | 대표 문구 |
|---|---|---|
| `정관no` | 정관이 날짜를 고정하지 않고 이사회(주총) 결의로 정한다 — 2023년 배당절차 개선 뒤 표준정관 | "이사회 결의로 제1항의 배당을 받을 주주를 확정하기 위한 기준일을 정할 수 있으며, … 2주 전에 공고" |
| `정관yes` | 결산기말 현재 주주로 고정 — 옛 표준정관 | "제1항의 배당은 매 결산기말 현재의 주주명부에 기재된 주주 또는 등록된 질권자에게 지급한다" |
| `정관yesorno` | 결산기말이 원칙이고 이사회가 따로 정할 수도 있다 | "매 사업연도 종료일 현재 … 지급하되 … 단, 회사는 이사회결의로 배당을 받을 주주를 확정하기 위한 기준일을 정할 수 있으며" (한화리츠) |
| `확인필요` | 본문이 없음(보호 PDF 등)·발췌 부족·조문 모순 | — |

태그는 **결산배당** 기준이다. 중간배당(상법 제462조의3)·분기배당(자본시장법 제165조의12) 기준일은 `interim`·`quarterly` 열에 따로 둔다.

## 작업 흐름

케이스 폴더 `kospi-charter/` 의 스크립트를 차례로 쓴다. 정관 전문이 이미 텍스트로 있어야 한다(`charter_fulltext_txt` 열 — 텍스트 정관은
`charter.txt`, 스캔은 Opus 전사 `charter_llm.txt`, PDF 는 `charter_pdf.txt`).

1. **발췌** — `python -X utf8 scripts/s09a_dividend_excerpt.py` (다른 표: `--sfx kosdaq --src data/final/kosdaq_charter.json`)
   정관 전문 대신 키워드 주변만 넉넉히 잘라 `data/interim/s09a_excerpts.jsonl` 에 둔다. 코스피 825사 기준 전문의 33%, 중앙값 5,100자.
2. **시험** — `python -X utf8 scripts/s09b_dividend_tag_llm.py pilot --codes …` 로 유형별 대표 회사 15~20곳을 동기 호출해
   태그·인용·비용을 본다. pilot 결과(`p_` 접두어)는 본 결과에 쓰이지 않는다.
3. **배치** — `s09b … submit` → `status` → `collect`. Claude Opus 5.5 · Batches(반값) · 구조화 출력. 코스피 825사 약 $13~15.
4. **검증·결과표** — `python -X utf8 scripts/s09c_dividend_build.py --queue`. 결과는 `data/final/charter_dividend_record_date.json·csv`.
5. **사람 검토** — `--queue` 에 나온 회사(`review=True`)를 정관 원문으로 확인하고 `data/interim/s09_review.json` 에
   `{"종목코드": {"tag": "…", "by": "누가", "at": "YYYY-MM-DD", "why": "근거"}}` 로 적은 뒤 s09c 를 다시 돌린다.
   발췌가 모자라 `확인필요` 가 나온 회사는 `s09b … full --codes …` 로 정관 전문을 보내 다시 본다.
6. **제출 뒤 안건** — `python -X utf8 scripts/s09d_dividend_after_agm.py`. 사업보고서 원본 제출 뒤 소집공고의 '정관의 변경' 절에
   기준일 문구가 있는 회사만, 안건이 원안대로 가결되면 태그가 무엇이 되는지 본다(동기 호출). s09c 를 다시 돌리면 `tag_after_agm` 에 붙는다.

7. **가결 확인** — `python -X utf8 scripts/s09e_agm_result_kind.py`. 기준일 조항을 바꾸는 안건마다 KIND 주주총회결과 본문의
   【주주총회 안건 세부내역】에서 가결여부를 읽는다. 배당 세부 안건('배당제도 개선의 건' 등 — 제목에 '정관'이 없을 때가 많다)이 있으면 그 행으로,
   없으면 정관 안건 전체로 판정. 옛 서식(2024년 이전)은 '제2호 의안:정관 일부 변경의 건 ☞ 원안대로 승인' 글에서 읽는다. KIND 는 분당 40요청 이하.
8. **확인필요 대체** — `s09f_prev_charter.py fetch → transcribe → tag`. 첨부 정관이 잠긴 PDF·결손이면 전년도 사업보고서 정관을 받고(잠겼으면 그 전 해),
   그 사이 소집공고 안건으로 바뀐 것을 반영한다. 어느 해 정관도 못 읽으면 사업보고서 본문 '배당관련 예측가능성' 표(2024.12 서식 개정 뒤 —
   '정관상 배당기준일을 배당액 결정 이후로 정할 수 있는지 여부' O/X)와 소집공고 '정관의 변경' 대비표로 판별한다. **DART 웹은 다른 수집과 동시에 쓰지 않는다.**
9. **지금 태그·근거 → 웹페이지** — s09c 를 다시 돌려 `tag_current`·`basis_kind` 를 만들고, `s09g`(근거 조항·스캔 쪽 잘라 내기) → `s10`(site/dividend.js).

### 코스피 실측 (2026-11-16)

- 825사 → 첨부 정관 `정관no` 437 · `정관yes` 378 · `정관yesorno` 7 · `확인필요` 3 → **지금** `정관no` 449 · `정관yes` 369 · `정관yesorno` 7
  (제출 뒤 주총 9사 KIND 가결 확인, 확인필요 3사 대체 자료).
- 비용: pilot 21사 $0.70 · 배치 823건 $13.52(회사당 약 $0.016) · 전문 재판별 1건 $0.10 · 안건 27건 $1.16.
- 인용 825/825 원문 일치. 규칙과 일치 694, 규칙 보류 121, 불일치 10(모두 규칙 오류). 사람 검토 41건 중 3건만 LLM 과 다르게 정했다.

### API 없이 — Claude Code 서브에이전트로 판별 (코스닥, 2026-11-16)

사용자가 API 비용 대신 세션 안에서 하자고 하면: `s09b … pack` → 서브에이전트 → `s09b … ingest`. 기준·입력·결과 형식이 API 와 같아 s09c 이하가 그대로 돈다.
- `pack --chars 100000` — 회사마다 API 사용자 메시지를 `in/{code}.txt` 로(긴 줄 1,000자 줄바꿈), 10만 자 이하 묶음(약 15사). 서브에이전트 하나에 한 묶음,
  `지시.md`(tagging-guide 8~60행만 읽기 · Read/Write 만 · 회사마다 바로 `out/{code}.json`) + 종목코드 목록만 넘긴다. 동시 20개가 한도.
- **먼저 코스피 결과가 있는 회사 10여 곳으로 시험**해 API 와 맞춰 본다(코스닥 때 14사 중 12사 같음, 다른 2사는 사람이 API 를 고친 회사).
- 묶음마다 같은 서식을 다르게 내므로(스팩 잔존 문구 → 정관yesorno·정관no·확인필요가 섞임) **서식별로 정규식으로 갈라 한 기준으로 맞춘다** —
  `s09h_kosdaq_review.py`, 기준은 tagging-guide 끝 '코스닥에서 자주 본 서식'.
- 제출 뒤 안건(`s09d --pack/--ingest`)·확인필요 대체(`s09f fetch` → 서브에이전트 → `s09f ingest`, 스캔 전년도 정관은 서브에이전트가 이미지를 읽어 `charter_llm.txt` 전사)도 같은 방식.
- 코스닥 실측: 1,784사 → 지금 `정관no` 758 · `정관yes` 824 · `정관yesorno` 202. 서브에이전트 약 140개, 묶음당 15~17만 토큰.

같은 표를 다시 돌려도 이미 받은 결과(`d_`·`f_`)는 다시 보내지 않는다. **지침을 고치면** 프롬프트 해시가 바뀌므로 결과 파일을
치우고(또는 `--sfx` 를 새로) 다시 보낸다 — `s09c_summary.json` 의 `prompt_sha256` 이 하나여야 한 기준으로 단 태그다.

## 발췌 원칙 (s09a)

- 정관 서식이 제각각이라(괄호 없는 조 머리, `제42조 | (이익배당)`, 한자 정관 `第39條 (配當)`, 외국 법인의 `16.11` 번호식, 줄바꿈 없는
  한 줄 원문) **조문을 나누지 않고 키워드 앵커 앞뒤 창**을 잘라 겹치면 합친다.
- 앵커는 한글·한자를 같이 잡는다: 배당을 받을/수령, 배당기준일, 질권자, 결산기말·사업연도 종료일 현재, 조 머리 뒤의 '배당',
  최종의 주주명부, 기준일, 주주명부의 폐쇄·기재변경, 중간·분기배당.
- 지급 대상 문구 바로 옆의 `제N조` 참조("제13조 제1항에서 정한 날 현재")는 그 조를 찾아 창을 하나 더 연다 — 참조형 정관이 꽤 있다.
- 앵커 이름을 발췌 머리말에 넣지 않는다(LLM 에 힌트가 되고 규칙 판별 정규식에 걸린다).
- 누락 점검: 전문에서 결정 문구(배당을 받을 주주를 확정하기 위한 기준일, 질권자에게 지급, 결산기말 현재, 최종의 주주명부 …)와,
  앵커에 없는 표현('주주명부에 기재된 주주' 근처의 '배당')이 모두 발췌 창 안에 드는지 센다. 코스피에서 결정 문구 2,699곳 전부,
  보조 표현 567곳 중 556곳이 들었고 빠진 11곳은 상환주식 통지·외국 법인 송금 절차였다.

## 판별 원칙 요약 (자세히는 tagging-guide.md)

1. 결산배당 조를 먼저 찾고, 각 문구가 **어느 조(결산배당·중간배당·분기배당)** 에 속하는지 가린다. 중간배당 조의 "이사회 결의로 …
   기준일을 정할 수 있으며"를 결산배당으로 읽는 것이 가장 흔한 오판이다.
2. '주주명부의 폐쇄 및 기준일' 조의 "12월 31일 … 정기주주총회에서 권리를 행사할 주주"는 의결권 기준일이다. 배당 조가 이사회 결정이면 `정관no`.
   기준일 조가 배당을 **명시**해 고정하면("배당을 수령할 권리") 결산배당 기준일로 본다.
3. 고정 문구와 이사회 결정 문구가 결산배당에 대해 둘 다 살아 있으면 `정관yesorno` — 같은 문장의 '단서'든 다른 항이든.
4. 금전배당과 주식배당이 갈리면 금전배당으로 태그하고 `note` 에 남긴다. 삭제된 항·개정 전 문구·연혁표는 보지 않는다.
5. 참조형은 끝까지 따라간다. 참조된 조가 "주주총회의 소집 기타 필요한 경우 이사회의 결의로 정한 날"뿐이면 정관 어디에도 고정일이 없으므로
   `정관no` 다(HD현대 계열). 결산일이 아닌 고정일("3월 7일 24시", "매년 1월 31일")은 `정관yes` + `fixed_point` 로 구분한다.

### 사람 검토에서 자주 본 편집 오류

- **같은 항 번호가 둘** — 새 문구에 `개정('23.3.22)`, 옛 문구에 `신설('22.3.23)` 이 붙어 나란히 남은 경우(현대모비스). 같은 항을 나중에 개정했다는
  표시가 있으면 옛 문구가 지워지지 않은 것으로 보고 새 문구로 태그한다. 표시가 없으면 문면대로 `정관yesorno`(조문 간 충돌 가능)로 둔다.
- **참조 항 번호 오기** — 배당 조가 삭제된 항(`① <삭제>`)이나 임시주총용 항을 가리키는데, 정기주총 조 등 다른 조도 같은 번호로 결산기 최종일을
  가리키면 항이 당겨진 오기로 본다(퍼스텍, 쏘카).
- **사업보고서에 주총 안건 반영본을 미리 첨부** — 개정 표시 날짜가 첨부일보다 뒤다(보해양조). 태그는 첨부본대로 단다.
- **첨부 정관이 일부 쪽만** — DART 이미지가 중간 조에서 끝난다(SK이터닉스). 전문 재판별로도 안 되면 `확인필요`.
- **스팩 서식의 소멸시효 조 잔존 문구** — 이익배당 조는 이사회 기준일로 고쳤는데 배당금지급청구권 소멸시효 조 ②에 "제1항의 배당은 매결산기말 현재 …"가
  남았다(그 '제1항'은 소멸시효 조 ①). 옛 문구로 보고 `정관no`(코스닥 스팩 29사).
- **원문 낱말 사이 제어문자** — 텍스트 정관에 `\x01` 이 끼어 인용 대조가 어긋난다(셀레스트라). 대조 함수가 제어문자를 공백처럼 다룬다.

## 검증 (s09c)

- **인용 대조**: LLM 인용(`quotes`)이 보낸 글에 공백 무시로 그대로 있는지. 없으면 review.
- **규칙 판별**: LLM 과 따로 정규식으로 결산배당 조의 '이사회가 정함'(B)·'결산기말 고정'(F)을 찾아 비교한다. 다르면 review.
  규칙은 주식배당 예외·조문 충돌처럼 못 가리는 경우가 있으니 판정이 아니라 **다시 볼 목록을 고르는 거름망**이다.
- **제출 뒤 정관변경**: 태그는 사업보고서 첨부 정관 기준이다. 그 뒤 소집공고 '정관의 변경' 절에 배당·기준일 낱말이 있으면
  `later_amend_dividend` 로 표시한다(그 주총에서 바뀌었을 수 있다).

## 주의

- 태그는 **사업보고서에 첨부된 정관 시점**이다. 12월 결산 회사는 대개 3월 정기주총 직전 정관이라, 그 주총에서 고친 내용은 빠진다.
  사업보고서보다 먼저 접수된 그해 정기주총 소집공고의 '정관의 변경'까지 보아야 한다(s09i, 2026-11-17 — 상장협 집계와 59사 차이의 원인이었다).
- **사업보고서가 없는 상장회사**는 상장 형태에 따라 '그 회사의 정관'이 붙은 문서를 쓴다(kospi-charter docs/01 R8-7).
  신규상장 = 증권신고서 첨부 정관 · 인적분할 재상장 = 모회사 회사분할결정 공시 '계약서(계획서)' 안 분할신설회사 정관(안)
  (그 공시의 '정관' 첨부는 모회사 정관이라 쓰지 않는다) · 신설합병 = 합병계약서의 신설회사 정관 ·
  스팩 소멸합병 상장 = 합병 증권신고서 정관 첨부 중 존속회사 부분(함께 붙은 스팩 정관은 뺀다) · 스팩 존속합병 = 합병 뒤 정관
  (사업보고서가 합병 전이면 합병 승인 주총의 '정관의 변경') · 투자회사 = KIND 기타신고사항 정관 개정 공지.
- 보호 PDF(Azure Information Protection)처럼 본문을 읽을 수 없는 정관은 LLM 에 보내지 않고 `확인필요` 로 둔다.
- 스캔 정관은 글자 인식 결과다. 인용할 때는 `charter_url` 의 원본 이미지와 대조한다.
- 2026-11-17부터 Claude API 는 쓰지 않는다(사용자 지시). 판별·스캔 전사는 `pack` → 세션 안 서브에이전트 → `ingest` 로 한다.
  옛 API 경로(pilot·submit·collect)는 기록으로만 남긴다.
