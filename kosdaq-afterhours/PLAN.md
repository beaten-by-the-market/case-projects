# 설계 문서: 코스닥 애프터마켓 저유동성 종목 배제 연구

> **결과는 [REPORT.md](REPORT.md), 현재 상태·인수인계는 [HANDOFF.md](HANDOFF.md)를 보라.** 이 문서는 **왜 이렇게 설계했는가**를 남긴다. 분석은 완료됐고, 아래는 최종 실행된 설계다. **원래 계획에서 바뀐 것은 §7에 따로 모아 두었다.**

## 1. 정책 주장과 검증 구조

**결론이 되어야 할 문장:**

> **저유동성 코스닥 종목은 별도의 객관적 기준을 마련해 애프터마켓에서 거래되지 못하게 해야 한다.**

**"전종목 반대"가 아니다.** 거래소는 이미 투자경고·투자위험·관리종목·투자주의환기·초저유동·투자유의를 애프터에서 빼기로 했다. **그런데 유동성 기준이 없다.** 이 연구는 **그것들을 다 빼고 남은 정상 종목들만으로도** 문제가 성립함을 보인다. 최종 산출물은 **시행 가능한 배제 규칙**이다.

| | 검증 | 결과 |
| --- | --- | --- |
| **H1** | 코스닥 거래대금은 극소수에 집중된다 | ✅ 하위 50%(841종목)가 거래대금의 **6.8%** |
| **H2** | 저유동성 종목은 거래대금 대비 공시 부담이 크다 | ✅ 단위 거래대금당 **143배** |
| **H3** | 한계 종목의 애프터 수익은 인건비를 회수하지 못한다 | ✅ 하위 담당자들은 애프터 거래대금이 사실상 **0** |
| **H5** | 저유동성 종목은 가격충격이 커서 애프터에서 위험하다 | ✅ Amihud D10 = D1의 **61배** |
| **H4** | 시행 가능한 배제 기준이 존재한다 | ✅ **5억 컷 + 히스테리시스** |

## 2. 핵심 설계 결정

### 2.1 수수료율은 가정하지 않고 역산한다

거래소 수수료율은 확정할 수 없다. **가정하는 대신 결론으로 뽑는다.**

> "이 종목들이 담당자 1인 인건비(연 1억)를 회수하려면 **수수료율이 몇 %여야 하는가?**"

읽는 사람이 자기가 아는 현실 수수료율과 직접 대보게 만든다.

### 2.2 애프터 거래대금은 NXT 일별 거래대금으로 **상한**을 잡는다

NXT 일별 거래대금(m223)은 **프리 + 메인 + 애프터가 섞인 값**이라 애프터 단독보다 반드시 크다. 이걸 "한계 종목이 애프터에서 벌 수 있는 금액의 **후한 상한**"으로 쓴다.

> **이 상한으로도 인건비가 회수 안 되면, 실제 애프터는 더 작으므로 결론은 자동으로 강해진다.** 가장 유리한 가정을 깔아주고도 지는 구조. 분봉으로 정밀하게 재는 것보다 반박하기 어렵다.

**분봉은 수집하지 않는다.** α(애프터/정규장 비율) 같은 임의 파라미터가 필요 없어진다.

### 2.3 NXT는 영리 사업자의 "선별" 벤치마크

NXT는 영리 ATS다. **돈을 벌어야 하는 사업자가 어디까지만 손대는지의 직접 측정치.**

**⚠ `code_info`를 NXT 거래허용 목록으로 쓰지 말 것.** `m223/code_info`(1,817)는 `m003/code_info`(1,820)를 그대로 비추는 미러다(교집합 1,817). **한계**: "안 열어준 것"과 "열었는데 거래 0"을 구분할 수 없다 → NXT 실거래 종목집합은 **선별 규모의 하한**으로만 해석한다.

### 2.4 비용은 인력 단위로 센다

**공시담당자 1인 = 담당 70종목 = 연봉 1억** (실제 운영 기준, 확정). → 코스닥 1,683종목 = **25명 = 연 25억**.

### 2.5 유니버스: 무엇을 세는가 (★ 가장 많이 고친 부분)

**출발점은 "현재 상장 종목"이 아니라 "그날 상장돼 있던 종목"이다.** `rank_invest_date`가 조회일 시점 상장 전종목을 주므로 **상장폐지 종목이 포함**된다. 빼면 **생존편향**이 생긴다.

**⚠ 거래소가 빼기로 한 유형은 종목 단위가 아니라 일자 단위로 걸러야 한다.** 종목 단위로 빼면 유니버스가 **46% 날아가고 거래대금의 54.5%를 잃는다.** 투자경고가 **급등한 대형주**에 붙기 때문이다(배제 종목 decile: D1 80개 vs D10 4개).

→ **(종목, 거래일) 편입가능 마스크**를 만든다(`status.py`). 상세 규칙은 **REPORT.md 부록 B**.

| 걸러낸 것 | 규모 |
| --- | --- |
| 지정·정지 상태 종목-일 | 종목-일의 **7.7%** · 공시의 **18.0%** |
| 스팩 | 173종목 |
| 우선주 | 3종목 |
| 편입가능일 120일 미만 | 78종목 |
| 전 기간 체결 0건 | 1종목 |
| **최종 유니버스** | **1,683종목** (상폐 14 포함) |

**⚠ 스팩·우선주 판정은 마스터 플래그만 믿으면 안 된다.** `F33792`(스팩)는 `code_info`(**현재 상장분**)에서 오므로 **합병으로 소멸한 스팩엔 플래그가 없다**(81종목). `F34501`(증권그룹ID)은 **우선주도 `ST`로 준다.** 둘 다 별도 판정이 필요하다. 상세는 **REPORT.md 부록 A**.

### 2.6 근거와 제안을 다른 문서에 담는다

**REPORT = "왜 배제해야 하는가"** (검증 대상) · **PROPOSAL = "무엇을 하자는 것인가"** (협상 대상).

섞어 두면 두 방향으로 무너진다. 제안이 싫은 사람이 **근거를 공격**하고, 근거를 인정하는 사람도 **제안의 세부(5억이냐 3억이냐)에서 발이 묶인다.** 분리하면 "근거는 맞다, 기준선만 조정하자"가 가능해진다.

### 2.7 비용 산정 대상 = 수시공시뿐

공시 피드는 **기업 수시공시 + 거래소 시장조치·통계·상장처리**가 섞여 있다. **공시부 심사 물량은 수시공시(기업 제출 + 주요사항보고서)뿐**이므로 나머지는 뺀다.

**코드 필드로는 못 가른다**: `BIGCD`·`BONCD`·`SRCCD` 등은 전부 단일값이고, `MTVCD`는 시장 구분이다. **제목에 "주요사항보고서" 문자열도 없다**(거래소 스트림이라 항목이 개별 제목으로 온다). → **블랙리스트**(거래소가 스스로 내는 것을 뺀 나머지 = 수시공시). 화이트리스트는 31%가 샌다.

이 정의는 **우리 주장에 불리한 쪽**이다(비용을 작게 잡음). 그럼에도 결론이 서면 강건하다.

- **`data_list`로 필드를 줄이지 않으면 즉시 한도 초과.** 없는 F-code는 **조용히 버려진다** → 요청·반환 대조 필수.

## 4. 분석 설계

### H1: 유동성 분포·집중도·NXT 선별 (`analyze.py`)
decile표(누적 점유율 포함) · 로렌츠/지니 · 절대 컷 · **NXT 거래 종목 비율**.

> **⚠ NXT는 거래대금 침투율이 아니라 종목 비율로 본다.** 거래대금 기준은 단조롭지 않다 (D8 3.2% > D7 2.4%. 소수 종목의 큰 거래 하나가 구간 비율을 흔든다). **"영리 사업자가 어디까지 손대는가"** 라는 질문에는 **종목 수 비율**(D1 89.2% → D10 0.0%)이 정확히 답한다.

### H2: 공시 부담 (`analyze_h2.py`)
**⚠ 핵심 지표는 절대 건수가 아니라 "거래대금 단위당 공시 건수"다.** 절대 건수는 **대형주가 더 많다**(1.60배). 여기서 논증이 갈린다.
+ **애프터 시간대(15:40~20:00) 공시**만 따로. 애프터 개설로 생기는 **증분** 부담.
+ **메인 차트**: 누적 거래대금(수익) vs 누적 애프터공시(비용) 두 곡선의 벌어짐.

### H3: 수수료율 역산 (`analyze_h3h5.py`)
70종목씩(담당자 1인) 끊어 "1억 회수에 필요한 수수료율" 역산. 분모는 NXT(=상한) → **가장 후한 하한**.

### H5: 가격충격 (`analyze_h3h5.py`). **권고의 1순위 근거**

**a fortiori 구조 (반박하기 어렵다):**
> 저유동성 종목은 **정규장에서조차** 소액 주문으로 가격이 크게 움직인다. 애프터는 정규장보다 유동성이 **더 얇다**. ∴ 애프터 위험은 **필연적으로 더 크다.**

**⚠ Amihud만 쓴다.** 일간 변동성·극단수익률은 **D1이 더 크다**(코스닥 대형주 = 테마·바이오 고변동주). 논거는 "많이 움직인다"가 아니라 **"적은 돈으로 움직인다"** 이다. **⚠ 무거래일을 섞으면 안 된다**: 평균이 희석돼 결과가 거꾸로 나온다.

### H4: 배제 기준 설계 (`rules.py`). **최종 산출물**

규칙이 되려면: ① 사전 관측 가능 ② 안정적 ③ 형평성 방어 가능.

**작동하는 기준은 유동성뿐이다:**

| 후보 | 결과 | 판정 |
| --- | --- | --- |
| 일평균 거래대금 | 포기 애프터 거래대금 0.32% | **채택** |
| 시가총액 < 500억 | 정규장 거래대금 **9.0% 포기** | 기각 |
| 부실 지정(불성실공시 등) | 애프터 거래대금 **16.4% 포기** | **기각** |

**⚠ 기준선을 하나만 두면 안 된다.** 단순 "5억 미만 제외"는 제외 명단이 반기마다 **44% 물갈이**된다. **히스테리시스**(제외 <5억 / 재편입 >10억)로 **30%**까지 낮춘다.

## 6. 산출물

**근거와 제안을 분리한다.** 근거는 검증받아야 하고 제안은 협상 대상이다. 한 문서에 섞으면 근거를 공격해 제안을 무너뜨리거나, 제안이 싫어서 근거를 안 읽는 일이 생긴다.

## 8. 남은 한계

1. **NXT 거래대금은 애프터 단독이 아니다** (상한으로만 사용).
2. **NXT의 "선별" vs "거래 0"을 구분할 수 없다** (하한으로만 해석).
3. **애프터 세션을 15:40~20:00으로 가정** (`classify.py::is_after_hours`).
4. **공시 본문 검증은 표본**(유형별 12건).
5. **정지 공시가 없는 정지는 잡히지 않는다.**
6. **수수료율은 역산 결과**다. 내부 수치를 넣으면 손익분기 종목수가 확정된다.
