# 핸드오프: 코스닥 애프터마켓 저유동성 종목 배제 연구

**상태: 분석 완료. 보고서·블로그 초안 완성. 커밋 안 됨.** 최종 갱신 2026-07-12 · **유니버스 1,683종목** · 606거래일(2024-01-01~2026-06-30)

---

## 1. 이 연구가 주장하는 것

> **저유동성 코스닥 종목은 별도의 객관적 기준을 마련해 애프터마켓에서 거래되지 못하게 해야 한다.**

**"전종목 반대"가 아니다.** 거래소는 이미 투자경고·투자위험·관리종목·투자주의환기·초저유동·투자유의를 애프터에서 빼기로 했다. **그런데 유동성 기준이 없다.** 이 연구는 **그것들을 전부 빼고 남은 정상 종목들만으로도** 문제가 성립함을 보인다.

### 핵심 문장

> **거래는 235배 적은데, 공시는 1.60배밖에 차이 나지 않는다.** 거래대금 100억원당 공시 부담은 **143배**.

### 최종 권고

**직전 반기 일평균 거래대금 5억원 미만 종목은 애프터마켓에서 배제한다. 재편입은 10억원 초과 시.**

| | 전종목 편입 | 권고안 |
| --- | --- | --- |
| 애프터 편입 종목 | 1,683 | **1,045** (638 배제) |
| 공시 담당 인력 | 25명 / 연 25억 | **15명 / 연 15억** |
| 포기 애프터 거래대금 | - | **0.32%** (NXT 기준 = 상한) |
| 애프터 시간대 공시 부담 | 100% | **67.0%** |

⚠ 638/1,045/0.32%는 **히스테리시스 반기 리밸런싱**(`h4_recommended.csv`) 결과다. `h4_rules.csv`의 "일평균 거래대금 < 5억" 행(제외 351)은 **단일 정적 컷**이라 값이 다르다. 혼동 금지.

> ⚠ **이건 내가 키워드로 고른 게 아니라 거래소가 실제로 정지를 건 사건이다.** 정지 공시 제목의 괄호에 사유가 있다(910건 100%). 산출: `scripts/halt_triggers.py` → `output/halt_events.csv`.

## 5. 방법론의 핵심: 일자 단위 제외

### 왜 종목 단위로 빼면 안 되나

거래소가 빼기로 한 유형을 **종목 단위**로 제외하면 유니버스가 **46% 날아가고 거래대금의 54.5%를 잃는다.** 투자경고가 **급등한 대형주**에 붙기 때문이다(배제 종목 decile 분포: D1 80개 vs D10 4개).

→ **(종목, 거래일) 단위 마스크**를 만들었다(`status.py` → `data/ineligible_days.csv`).

### 규칙 요약 (상세 명세는 REPORT.md 부록 B)

**규칙 A. 투자경고·투자위험·관리종목·투자주의환기** (공시로 구간 복원)
- 판정 순서: `기타시장안내`/`우려` 버림 → `(정정)` 버림 → **`해제`(단 `일부해제` 제외)** → `예고` 버림 → 나머지=지정
- 제외 구간 = [지정 공시일 **다음 거래일** … 해제 공시일]
- **A-9 좌측절단 보정**: 구간이 안 열린 채 해제를 먼저 만나면 = 기간 이전 지정 → 첫 거래일부터 제외

**규칙 B. 매매거래정지** (공시 + 거래량)
- `주권매매거래정지` 910건 / `기간변경` 521건(**무시**) / `해제` 468건
- **정지 공시일은 무조건 제외**(장중 정지 시작일에도 거래는 있다) + 구간 내 무거래일 + 해제 후 첫 거래일 전날까지
- **B의 좌측절단 보정도 필수** (위 버그 #1)

**규칙 C. 초저유동·투자유의**: 공시 NCD는 **본주** 코드다. 대상이 우선주면 코드를 변환해야 한다.

**규칙 D. 스팩존속합병**: **합병상장일 이전**을 제외. 정본 출처 = `data/spac소멸합병상장.xlsx` (KIND, 130건). 우리 기간과 겹치는 건 **2건**뿐이다. 씨피시스템(413630, 2024-06-27) · 지슨(446840, 2025-08-14). 공시 휴리스틱도 **정확히 같은 2종목**을 찾았다.

### ⚠ 규칙 A·B에서 네 번 틀렸던 지점

| 함정 | 무엇이 문제였나 |
| --- | --- |
| **`일부해제`를 해제로 처리** | 관리종목 해제류의 **40%**, 환기종목의 **22%** 가 `일부해제`. 여전히 지정 상태인데 구간을 조기에 닫았다 |
| **`예고` 제거를 `해제` 판정보다 먼저** | 해제 공시 제목이 **"투자경고종목 지정해제 및 재지정 예고"**. 해제 668건 중 667건이 사라졌다 |
| **`지정예고`를 지정으로 계수** | 투자경고 관련 2,802건 중 **2,059건(73%)이 예고**. 대상 종목이 442→730개로 부풀었다 |
| **`기간변경`을 새 정지로 계수** | 521건. 정지 이벤트가 1,440건으로 부풀었다(실제 910건) |

### 검증

- **공시 본문 대조**(`validate_dates.py`): 유형별 12건 표본, **전부 100% 일치**. 본문에 `2. 지정일 | 2026년 01월 22일` 처럼 실제 날짜가 있다. **전수 아님.**
- **좌측절단 31종목**: `gongsi_jong`으로 2020~2023 공시 조회 → **31/31 과거 지정 확인**. ⚠ `gongsi_jong`은 **`dcnt` 기본값이 100**이라 반드시 올려야 한다.
- **KRX `trading_halt`(MDCSTAT21301)는 못 쓴다**: **현재 정지 중인 종목만** 반환한다(해제된 정지는 0행). 6개 확정 정지+해제 종목으로 검증함. 우리 공시 기반 복원과 최종 유니버스가 동일해 **쓰지 않기로 했다.**

## 7. 실행 순서

**외부 의존:** 스크립트는 `C:\Users\Peter\github\check-api-krx-dl`의 checkapi-data 스킬(`.claude/skills/checkapi-data/scripts/_common.py`)을 `sys.path`에 절대경로로 넣어 쓴다. CHECK 자격증명(`CHECK_CUST_ID`/`CHECK_AUTH_KEY`)과 명세(`checkapi-specs.json`)도 그 레포에서 읽는다. 레포를 옮기면 각 스크립트 상단의 `sys.path.insert` 경로를 같이 고쳐야 한다.

python rules.py                            # 배제 기준 평가 + 히스테리시스

## 9. 남은 한계 (문서에 명시돼 있음)

1. **NXT 거래대금은 프리+메인+애프터 합계**다. 애프터 수익의 **상한**으로만 썼다. 모든 결론이 "상한으로 잡아도 회수가 안 된다"는 형태라 방향은 안전하다.
2. **NXT가 "안 열어준 것"과 "열었는데 거래가 0"을 구분할 수 없다.** 실거래 집합은 선별 규모의 **하한**.
3. **애프터 세션을 15:40~20:00으로 가정**했다. 제도가 다르면 `classify.py::is_after_hours` 수정.
4. **공시 본문 검증은 표본**(유형별 12건)이다.
5. **정지 공시가 없는 정지는 잡히지 않는다.**
6. **수수료율은 가정하지 않고 역산**했다. 내부 수치를 넣으면 손익분기 종목수가 확정된다.
